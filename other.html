MAR: Multi-Agent Reflexion Improves Reasoning Abilities in LLMs

Large language models can produce rich reasoning traces, but single-agent self-reflection often reinforces mistakes. We replicate the Reflexion framework, analyze its failure modes, and introduce a multi-agent extension that injects structured debate to deliver more reliable improvements on HotPotQA and HumanEval.

Abstract

Large Language Models (LLMs) have demonstrated impressive capabilities in reasoning and program synthesis, yet enabling them to improve through experience remains challenging. Traditional reinforcement learning requires expensive fine-tuning, so Reflexion introduced a verbal reinforcement loop in which the agent stores natural-language reflections as episodic memory. Our replication on HotPotQA and HumanEval confirms that single-agent Reflexion improves over prompt-only baselines, but it also exposes confirmation bias, repetitive reasoning, and limited corrective feedback. To address these issues, we propose Multi-Agent Reflexion (MAR), where several persona-driven critics debate a failed attempt and a judge synthesizes their insights into actionable reflections. MAR improves HotPotQA exact-match accuracy from 44% to 47% and HumanEval pass@1 from 76.4% to 82.6%, while also reducing stagnation in the reflection loop.

Introduction

LLM agents now interact with complex environments, but enabling them to learn from experience without costly weight updates is still difficult. Reflexion offers a lightweight alternative: generate natural-language feedback after each failed attempt, store it in memory, and condition subsequent reasoning on this history. While effective, this single-agent loop couples action generation, evaluation, and critique, which often leads to confirmation bias and mode collapse. Our study focuses on the HotPotQA multi-hop reasoning benchmark and HumanEval program synthesis, reproducing Reflexion’s pipeline with detailed instrumentation. The logged trajectories reveal that reflections frequently restate the same misconception rather than introduce new strategies, motivating a multi-agent extension that deliberately injects diverse perspectives.

Datasets & Metrics

HotPotQA

A Wikipedia-based benchmark for multi-hop question answering. Each question requires reasoning over multiple passages. We follow the original Reflexion setup: 100 curated dev-set questions, ReAct-style prompting, and a five-trial limit per item. Performance is reported using Exact Match (EM) after HotPotQA normalization.

HumanEval

A Python program synthesis benchmark. Each task specifies a function signature, description, and hidden unit tests. We evaluate pass@1 by executing each generated solution inside the official sandbox. Every problem receives one initial attempt and reflection-guided retries under the same budget used in the Reflexion paper.

Performance Metrics

  • Exact Match (HotPotQA): Predicted answers must match the normalized ground-truth string exactly.
  • pass@1 (HumanEval): Fraction of problems where the first sampled program passes all unit tests.

Methodology

We adhere closely to the public Reflexion implementation, keeping prompts, tool usage, and evaluation protocols aligned with the original study. Our replication uses GPT-3.5-Turbo for cost efficiency, with GPT-4 runs for HumanEval baselines. Detailed logging captures trajectories, evaluator decisions, reflections, and API usage, allowing us to diagnose where the loop succeeds or stagnates.

HotPotQA Pipeline

  • ReAct prompting with retrieval-style tool calls.
  • Five trials per example; reflections appended after each failure.
  • Same 100-question subset used by Reflexion for comparability.

HumanEval Pipeline

  • Sandboxed execution of each generated function.
  • One initial attempt, then a single reflection-guided retry (matching the original limited-budget setup).
  • Instrumentation of failure modes via log parsing.

The replication trends match the original claims: reflection-guided retries outperform prompt-only runs, though gains are slightly smaller with GPT-3.5. Inspection of reflection logs highlights systemic weaknesses—single-agent feedback often repeats the same faulty narrative, and strict EM scoring can penalize semantically correct HotPotQA answers.

Multi-Agent Reflexion (MAR)

To counter confirmation bias and mode collapse, MAR replaces the single self-reflecting critic with a small team of persona-driven agents. When the Actor fails, multiple critics analyze the trajectory, debate alternative hypotheses, and a judge synthesizes their insights into a consensus reflection stored in memory.

Debate Loop

  1. Actor attempts task using standard ReAct or program synthesis.
  2. Evaluator flags failure, triggering the debate stage.
  3. Debater personas (Verifier, Skeptic, Logician, Creative, etc.) write diagnoses of what went wrong.
  4. Judge elicits agreement/disagreement rounds (max two) to refine critiques.
  5. Judge synthesizes a consensus reflection that is appended to episodic memory for the next attempt.

Persona Axes

  • Evidence exploitation: strict proof vs. loose intuition.
  • Exploration: stick to known plan vs. propose new paths.
  • Specification strictness: tolerance for format deviations.

HotPotQA uses Verifier, Skeptic, Logician, and Creative personas; HumanEval uses Senior Engineer, QA Engineer, and Code Reviewer roles to mirror real-world code review workflows.

MAR consistently improves over single-agent Reflexion. Gains on HotPotQA are modest due to EM’s brittleness—several correct answers were rejected for minor formatting differences—but the qualitative behavior is better: agents escape repeated loops and surface clearer fixes.

Discussion

Why Single-Agent Reflexion Fails

  • Confirmation bias: The same model acts, evaluates, and reflects, so critiques often justify the original mistake rather than correct it.
  • Mode collapse: Retries reproduce nearly identical reasoning traces even after reflection, leading to stagnant improvement.
  • Metric brittleness: Exact-match scoring penalizes sensible answers, misleading the reflection process.

MAR Takeaways

  • Structured disagreement surfaces alternative reasoning paths that break mental-set failures.
  • Judge aggregation yields higher-quality reflections focused on actionable fixes.
  • Cost increases (≈3× more API calls) highlight a trade-off between diversity and efficiency.

Conclusions & Societal Impact

Multi-Agent Reflexion shows that we can obtain more reliable, self-correcting LLM agents without touching model weights. By coordinating multiple reasoning personas and a judge, MAR reduces confirmation bias and improves success rates on both reasoning and coding tasks. Future work includes lighter-weight debate protocols, dynamic persona selection, and more semantic evaluation metrics for datasets like HotPotQA.

The benefits of multi-agent reflection come with environmental and economic costs: more calls per task increase energy consumption and API expenses. Additionally, emergent behaviors in multi-agent systems can be harder to align. Responsible deployment requires both efficiency improvements and careful monitoring of long-lived autonomous agents.
